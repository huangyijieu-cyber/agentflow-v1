# Web / Wikipedia 全文阅读与摘要

Web 工具取消 embedding、相似度排序和 top-10 检索，改为读取抓取到的网页正文。
Wikipedia 仍先搜索候选条目、选择相关页面，然后逐页复用同一条全文摘要流程。
工具的外部名称和输入参数保持兼容，名称中的 `RAG` 不再代表网页处理方式。
Wiki 返回结构改为 `summary`（跨页综合摘要）和 `sources`（来源编号、标题、URL）；
不再返回多份单页摘要和重复简介。失败时返回明确说明。

## 处理过程

1. 从 HTML 提取正文，移除脚本、样式、导航栏、页脚等内容；保留标题、段落和表格行。
2. 正文及提示词加上预留输出空间能够进入上下文时，只进行一次摘要调用。
3. 超长正文按段落优先切分，必要时拆分句子或超长表格行；默认保留少量重叠。
4. 每一段都交给工具模型围绕原查询提取证据，没有相关证据的段落返回明确标记。
5. 将各段证据合并、去重，形成最终摘要。合并输入仍超长时，逐层分批压缩。
6. Wiki 将所有选中页面的摘要再次汇总，最终**一次 `tool.execute` 返回结果不超过
   2048 tokens**，包括来源元数据及单次执行的列表包装。通常多一次工具模型调用；
   汇总输入过长时仍分批处理全部页面的证据。

不再使用原先的前 100 万字符截取，也不只选择一部分正文片段。所有**提取到的正文**
都会参与处理；这不保证网页动态加载或需要登录的内容能被抓取。
每次模型调用都要求保留准确实体、数字、日期、限定条件、冲突和来源。
模型仍可能遗漏事实，真实回答质量需在验证集上比较。

## Token 预算

默认读取实际模型服务的 `/v1/models` 中 `max_model_len`，使用同一服务的 `/tokenize`
计数，并兼容 `/v1/tokenize`。训练代理提供这两个计数路由，使用已加载的训练模型 tokenizer。
正文预算会扣除系统提示词、查询、摘要指令、输出预算及 256 token 余量。
客户端配置的值只能进一步缩小已探测到的服务上限。

兼容性回退：无法探测服务上限时，使用显式配置或 8192 token；远程 tokenizer 接口
不可用时，优先加载该模型的本地/已缓存 tokenizer（不会自动下载）。只有本地 tokenizer
也不可用时，才按 UTF-8 字节数保守估算。这种回退会更早分段、可能增加调用次数，
它不是精确的模型 token 计数。智能体提示词不会仅因为字节估算超限而直接失败，
此时保留最新结果，让模型服务校验实际长度；真实超长请求仍可能被服务拒绝。
若服务上限低于回退值，必须显式设置对应环境变量。

可在启动现有运行脚本之前设置以下环境变量，无需修改 YAML：

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| `AGENTFLOW_WEB_CONTEXT_TOKENS` | 自动探测，失败回退 8192 | 工具模型的上下文预算上限 |
| `AGENTFLOW_WEB_SUMMARY_TOKENS` | 1024 | 短网页直接摘要、长网页最终摘要的最大输出 token 数 |
| `AGENTFLOW_WEB_EVIDENCE_TOKENS` | 512 | 每段证据提取、每批中间合并的最大输出 token 数 |
| `AGENTFLOW_WEB_OVERLAP_TOKENS` | 64 | 正文分段的最大重叠 token 数，同时不超过当前段字符数的四分之一 |
| `AGENTFLOW_AGENT_CONTEXT_TOKENS` | 自动探测，失败回退 8192 | Planner / Verifier 所用服务的上下文预算上限 |
| `AGENTFLOW_WEB_TOKENIZER_PATH` | 工具模型名称或路径 | 远程计数不可用时加载的本地 tokenizer 路径 |
| `AGENTFLOW_AGENT_TOKENIZER_PATH` | 当前智能体模型名称或路径 | 远程计数不可用时加载的本地 tokenizer 路径 |

这些变量只控制客户端预算，**不会修改 vLLM 的服务端上下文容量**。
工具模型和智能体模型可能是不同服务，分别探测其实际容量。

### Wiki 最终返回上限

2048 是固定总预算，按摘要工具模型（当前 30B）的 tokenizer 计数。先为来源标题、URL、
结构字段及序列化余量预留空间，再设置综合摘要的 `max_tokens`，所以摘要正文的生成
额度小于 2048。检查结果使用执行器列表包装后的 Python 字符串（历史实际使用的形式）
及普通 JSON 两者中较大的计数，不包含日志美化缩进、外层动作记录或其他历史。
没有可用 tokenizer 时采用 UTF-8 字节上界，可能得到更短的摘要。

最终实际计数超限时只再压缩一次；仍超限、来源元数据太长或汇总失败时，返回简短错误
结果，不抛出新的 rollout 预算异常，也不截取一段摘要假装完整。无搜索结果或未选中页面
时不调用汇总模型，直接检查提示信息和候选来源的长度。不会添加改写查询的建议。

如果 Planner 使用不同的 tokenizer，其计数可能不同；整个 Planner 提示词仍由现有
历史预算机制单独检查。这个上限不代表多轮历史、问题和指令合计一定能装进上下文。

日志中的 `[Web summary] direct` 表示一次直接摘要；`extracting segment` 表示分段提取；
`final merge` 表示最终合并。`[Context budget]` 会提示探测或计数回退情况。

## 摘要进入智能体

- 默认取消工具结果的前 2000 字符截断，最近三步窗口与命令的 500 字符限制保留。
- Wiki 新结果的 `summary` 和 `sources` 完整进入模型可见历史及过程记录。
  历史兼容逻辑仍能读取旧的 `relevant_pages` 结果；新结果不再携带各页摘要原文。
- Planner 下一步决策、Verifier、详细回答和直接回答均检查**完整提示词**的预算，
  包括问题、初始分析（相应提示词包含时）、工具说明、历史与 2048 token 输出空间。
- 超出预算时，优先将较旧结果替换为带有省略标记的工具/子目标记录，必要时再移除旧记录。
  这一步是明确地省略旧证据，没有调用模型对历史进行语义摘要。
- 最新一步的完整结果不作字符截断。如果精确计数表明它与问题、提示词本身无法放入上下文，
  会明确报预算错误，需要减少工具摘要输出长度或调整实际服务容量。
- 同一步号重新写入时会更新其在时间窗口中的位置；本次未增加跨样本清空机制。

## 耗时与失败处理

长网页的分段调用按顺序执行，避免在当前 rollout 并发之外再增加工具内部并发。
分段增多会增加模型调用次数，仍受原有工具执行超时限制。
执行器发出超时取消信号后，摘要任务在下一次预算检查/模型调用前退出；已发送的模型
请求无法由此取消。

模型返回空文本、上下文容纳不了查询、合并不能继续缩短、合并超过 12 层时，显式报告
失败，不返回截掉末尾的部分摘要。Wiki 单页失败的 URL、错误说明交给跨页汇总，
要求明确区分抓取失败与事实证据；汇总本身失败则返回简短错误结果。
网页请求原有的网络重试策略保留。

## 本地验证

在项目根目录执行：

```bash
python3 -m unittest discover -s tests -p 'test_page_summary.py' -v
python3 -m unittest discover -s tests -p 'test_context_proxy.py' -v
```

测试使用模拟模型响应和模型服务元数据，不访问真实 30B、embedding 服务或网站。
覆盖短文完整输入、长文尾部证据、分层合并、中文无空格长段、HTML 表格清理、
上下文预算回退、Wiki 跨页汇总与 2048 总上限、尾页证据进入历史、超限再压缩及失败兜底、
Planner/Verifier 提示词接入，以及失败和取消路径。
代理测试需要项目已有依赖 Flask，覆盖空请求体的 `/v1/models`、两个 tokenizer 路由、
普通聊天请求及完整预算检查流程，无需 GPU/训练依赖。

## 代理兼容性修复

旧训练代理只转发 `/v1/*`，没有 `/tokenize`；此外，它对成功的 GET 请求也解析请求体，
使原本成功的 `/v1/models` 在空请求体处报错，触发 8192 token 回退预算。
修复后 GET 可以正常透传，并提供本地 tokenizer 路由。
更新代码后应重启本次验证任务的训练代理和 rollout 服务，旧进程不会自动加载新路由。
网页摘要的 30B 上限与训练 Planner 的模型上限分别探测，不能把前者的 32768 直接套给后者。
